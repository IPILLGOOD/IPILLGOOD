# 공개 알약 사진 검수·특징 추출 실험 (#123)

팀원은 [공통 자료로 시작하기](pill-photo-team-guide.md)를 먼저 참고한다. 검수된 사진 9장·압축 카탈로그·기준 JSON을 `backend/test-support/pill-photo-fixtures/`에 선별했으며, `pill:replay`로 API 키 없이 과거 결과를 비교하고 `pill:regression`으로 안전·검색 회귀를 검사할 수 있다. 아래 최초 실험 기록은 그대로 보존한다.

## 현재 결론 — 최초 2026-08-31, 리뷰 반영 2026-09-01

**검수한 공개 사진을 특징 추출기에 넣고 전체 식약처 카탈로그와 비교하는 로컬 실험을 구현했다. 사용자 사진 식별 기능의 출시 완료가 아니다.**

첫 실제 실행은 6건 모두 API 응답·구조 검증에 성공했지만, 기대 품목 후보 포함은 **0/4**였다. 예외 2건은 모두 재촬영으로 반환됐으나, 의도한 예외 원인까지 감지한 것은 **1/2**였다. 안전한 결과 상태가 나왔다는 사실과 올바른 특징을 읽었다는 사실을 구분한다.

따라서 현재 추출 설정을 사용자 기능에 연결하면 안 된다. 다음 우선순위는 각인 판독·제형/모양 분류·이미지 손상 감지를 개선하고 더 다양한 독립 사진으로 평가하는 것이다. 벡터 DB 도입이나 후보 기준 완화를 먼저 할 근거는 아직 없다.

2026-09-01 리뷰 반영 후에도 정상 사진의 기대 후보 포함은 **0/4**로 변하지 않았다. 다만 복수 각인 관찰 계약, 각인 우선 후보 생성, 시각 특징 conflict 재정렬, 실패 가능한 회귀 명령을 추가했고, 잘린 공개 사진의 기대 예외 원인 감지는 **1/2 → 2/2**로 보완했다. 이는 저장된 사진 특징과 검수 PNG의 로컬 마스크를 현재 규칙으로 재생한 결과이며 AI를 새로 호출한 성능 개선 수치가 아니다.

## 구현 흐름과 범위

```text
검수 명세의 공개 사진 앞·뒷면
  → 원본 크기·SHA256 허용 목록 확인
  → 투명 알파 마스크 오목함을 로컬 품질 보조 신호로 기록
  → 알파 경계 자르기·흰 배경 합성·최대 1024px·메타데이터 제거
  → OpenAI에 사진 두 장 + 관찰 특징 계약만 전달
  → 엄격한 출력 구조 검증
  → 사진 손상 / 앞뒤 불일치 / 동일 면 의심 시 재촬영
  → 기존 searchPillCandidates (전체 카탈로그)
  → 비교 후보 / 정보 부족 보류 / 재촬영 / 비지원 / 미식별
  → 정답 품목코드와 사후 비교하여 JSON·HTML 보고서 저장
```

- 약명·품목코드·정답 특징·파일명·폴더명·검색 후보는 AI에 보내지 않는다. 사진 속 특징만 읽도록 한다. 기대 품목은 검색 후 평가와 보고서에서만 사용한다.
- 사용자에게 수동 특징 입력을 시키는 제품 흐름을 추가한 것이 아니다. 기존 검색기에 `source: image_features` 관찰값을 넣는 어댑터다.
- 전체 25,387개 레코드를 검색한다. 정답 4개만으로 카탈로그를 줄이지 않는다.
- 후보는 약 확정·복용 가능 판정·확률이 아니다. 복약 계획·알림·약품 등록으로 자동 연결하지 않는다.
- 서버 라우트·사용자 업로드 UI·외부 이미지 URL 입력·운영 배포·벡터 DB는 추가하지 않았다.
- Node 전용 실험 모듈은 backend 공개 export나 운영 앱에 연결하지 않았다. 기존 개발 의존성 `sharp`를 사용하며 패키지/lockfile 변경은 없다.

### 전송 경계

#123에서 선행조건으로 연결한 #61(민감정보 확인·마스킹)과 #88(외부 AI 전송 고지·동의)은 확인 시점에 미완료였다. 일반 사용자 사진 전송을 활성화하지 않는다.

현재 실험은 코드에 고정한 **9개 공개 파일의 크기와 SHA256이 정확히 일치할 때만** 전송된다. 파일은 Git 공통 fixture의 `images/`에서 읽는다. CLI에서 임의 사진·URL·허용 목록을 받을 수 없다. 허용 목록 확대도 출처·이용조건·개인정보·사진 내용 검토 후 코드 리뷰 대상이다. 해시는 모델 정확도 인증이나 동의 체계의 대체물이 아니다.

실제 호출에는 `--live --confirm-public-transfer` 둘 다 필요하다. 기존 개발 세트는 최대 6건을 순차 실행하며 현재 파이프라인은 사례당 Vision 1회·면별 OCR 2회, 전체 최대 18요청이고 재시도하지 않는다. 고정 평가 세트는 4건·최대 12요청이다. 인증 실패·429·통신 장애 등은 다음 호출을 중단한다. HTTP 400/422, 개별 응답 거절·구조 오류는 성공이나 식별 무결과와 구분한다.

공식 `https://api.openai.com/v1/responses`만 호출하고 리다이렉트를 금지한다. `store: false`, Vision 최대 출력 2,400토큰·OCR 최대 출력 1,400토큰, 요청당 90초 제한, 응답 256KiB 제한을 사용한다. 이는 외부 전송 자체가 없거나 제공자가 아무 데이터도 보존하지 않는다는 보장은 아니다. 실제 사용자 적용 시 데이터 처리 조건을 별도 검토해야 한다.

### 정답 연결 재검증 — 2026-09-02

평가 매니페스트 v2에는 위 접수번호 공개 근거와 고정 식약처 레코드 지문을 품목별로 기록했다. 가져온 시각만 지문에서 제외하며 품목코드·제품명·제조사·제형·모양·색상·양면 각인·공식 이미지 URL·공식 변경일은 보존한다.

```sh
# 고정 전체 카탈로그, 외부 요청 0회
npm run pill:labels --workspace @care-atlas/backend

# 현재 식약처 v03 API에 네 품목코드를 각각 조회, 외부 요청 4회
npm run pill:labels:live --workspace @care-atlas/backend
```

고정 카탈로그와 현재 API 모두 네 품목이 정확히 1건씩 조회됐고 공식 외형 및 레코드 지문이 일치했다. 이 검사는 **사진 정답이 어느 공식 품목과 연결되는지**를 검증할 뿐 사진에서 특징을 정확히 읽는지 또는 후보 검색이 정답을 포함하는지는 측정하지 않는다. 사진과 AI 추출값은 식약처 요청에 보내지 않는다.

### 전처리 범위

원본은 변경하지 않는다. 완전히 투명한 외곽만 자르고 흰 배경에 합성한 뒤 비율을 유지해 최대 1024px로 축소한다. 확대·색상 보정·대비 강화·회전·손상 복원은 하지 않았다. 알파 영역 안에 이미 지워진 부분은 복구하지 않는다. 원시 픽셀에서 새 PNG를 만들어 EXIF/XMP 등 메타데이터와 완전 투명 영역의 숨겨진 RGB를 제거한다. 이 처리는 **임의 사용자 사진의 개인정보 마스킹 구현이 아니다.**

- 비지원 제형, 파손, 여러 약/겹침, 앞뒤 쌍 불일치, 판독 불가능 품질은 기존처럼 후보 생성 전에 차단한다. 각인 근거가 없는 모양·색상 항목은 사용자 후보로 승격하지 않는다.

### 회귀 게이트와 diff

`pill:regression`은 `pill:replay`와 목적을 분리한다. 재생 보고서는 진단 결과를 항상 남기지만, 회귀 명령은 아래 조건 중 하나라도 깨지면 exit 1이다.

1. 서로 다른 약의 앞·뒷면 조합 후보 노출 금지
2. 잘린 공개 사진의 기대 품질 게이트 재촬영
3. 정확 각인 + 색상 오차에서 기대 후보 유지와 `colors` conflict 기록
4. 복수 각인 후보 중 공식 각인과 맞는 원문 후보 유지
5. 제한된 혼동 문자 확장 후보와 치환 근거 유지
6. 카탈로그 역순 입력에서도 표시 후보·보류 후보 순서 결정성 유지

실행 폴더의 `regression.json`에는 위 게이트의 기대/관찰값과 과거/현재 `candidates`, `heldCandidates`, 비교·검색 사유, 평가 결과의 diff가 들어간다. 현재 diff는 `two-color-capsule` 보류 목록 변화와 `image-cutout`의 정확한 거절 사유 변화를 기록한다. 양성 실사진 4건은 독립 승인 기준선이 생길 때까지 진단 지표로만 남기며 0/4에 맞춘 특례나 성공 게이트를 만들지 않는다.

## 실행 방법

API 키 없이 팀 공통 기준선을 보려면 저장소 루트에서 다음을 실행한다. `replay`는 저장된 AI 특징과 고정 카탈로그의 비교일 뿐 새 사진 인식이나 현재 데이터 조회가 아니다.

```sh
npm ci
npm run pill:verify --workspace @care-atlas/backend
npm run pill:replay --workspace @care-atlas/backend
npm run pill:regression --workspace @care-atlas/backend
```

세 `pill:*` 명령은 `verification-artifacts/`의 과거 다운로드나 보고서에 의존하지 않는다. `replay`는 새 HTML/미리보기를 만들고, `regression`은 내부 재생 결과와 `regression.json`을 새 `run-*` 폴더에 만든다. 생성물은 계속 Git에서 제외한다. 고정 JSON·gzip·사진은 검증 후 읽고 기존 수집 시각을 수정하지 않는다. `review`/`evaluate`의 최신성 검사에는 이 오프라인 예외를 적용하지 않는다.

저장소 루트에서 실행한다. 아래 기존 카탈로그 경로는 이 로컬 환경의 예시다. 다른 환경에서는 정상 수집·검증한 스냅샷 경로를 사용한다. 최신성 범위(1~168시간)는 명시적으로 정하며, 오래된 파일의 시각/해시를 고쳐 통과시키지 않는다.

```powershell
# 외부 전송 없음. Git에 포함된 사진을 사용하되 별도 최신 카탈로그가 필요하다.
node --experimental-strip-types backend/scripts/pill-photo.ts review --catalog verification-artifacts/pill-catalog/run-MLjAAj/catalog.json --max-age-hours 24

# 실제 외부 AI 호출/과금 발생. 검수된 공개 사진만, 최대 6건·사례당 최대 2요청.
node --env-file=front/.env.local --experimental-strip-types backend/scripts/pill-photo.ts evaluate --catalog verification-artifacts/pill-catalog/run-MLjAAj/catalog.json --max-age-hours 24 --live --confirm-public-transfer

# 한 사례만 시험하려면 마지막에 --case oval-tablet 등 고정 ID 추가
node --experimental-strip-types backend/scripts/pill-photo.ts --help

# 기본 회귀 테스트: 네트워크·로컬 사진 자료 불필요
node --experimental-strip-types --test backend/src/pill-photo.test.ts

# Git 공통 공개 샘플 검증. 전송은 모두 모의 응답, 외부 호출 없음.
node --experimental-strip-types --test backend/test-support/pill-photo-local.test.ts
```

`review`는 API 키 없이 실행한다. `evaluate`만 `front/.env.local`의 `OPENAI_API_KEY`·`OPENAI_MODEL`·`OPENAI_OCR_MODEL`을 로드한다. 한 사례에서 범용 Vision 1회와 첫째/둘째 면 각인 OCR 2회를 순차 호출하며 재시도하지 않는다. 따라서 기존 개발 세트 6건이 모두 세 단계에 도달하면 최대 18요청이다. 키·원문 오류·전체 API 응답을 출력하지 않고 실패 코드만 남긴다. 각 실행은 새 `run-*` 폴더를 만들고 이전 결과를 덮어쓰지 않는다. `replay`의 식별 누락/보류는 실행 장애와 다른 진단 결과라 exit 0일 수 있다. `regression`은 합의한 안전·검색 조건이 깨지면 exit 1이지만, **exit 0도 정상 실사진을 정확하게 식별했다는 뜻은 아니다.**
