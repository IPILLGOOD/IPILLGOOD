# 저장 Vision 고정 · OCR 지침 비교 준비 (#141)

## 이번 변경의 범위

사람 판독 오라클에서 각인 문자열을 교체하면 일부 후보 순위가 개선됐지만, 모델이 그 문자열을 실제로 읽을 수 있는지는 확인되지 않았다. 다음 가설 하나를 검사할 준비다.

> 기존 입력을 그대로 두고, 회전 방향·문자 획·색상/대비 이미지의 대응 위치를 확인하는 OCR 지침이 실제 판독을 개선하는가?

- 기본 OCR 지침 `pill-photo-imprint-ocr-per-side-dual-view-v2`는 바꾸지 않는다.
- 선택형 지침 `pill-photo-imprint-ocr-stroke-check-v3`만 추가한다. 기존 안전 문구를 보존하며 특정 약·품목코드·정답 각인 예시는 넣지 않는다.
- 출력은 기존 JSON 계약 그대로다. 설명이나 사고 과정을 출력시키지 않는다. 지침 추가가 정확도 향상을 보장하지 않는다.
- 새 지침은 development/phone_validation에만 허용한다. 동결 evaluation/holdout에는 적용하지 않는다.
- 이번 CLI는 **prepare만 지원**한다. `run`, `--live`, 임의 모델·사진 경로 옵션이 없고, API 키를 읽지 않는다.

OpenAI Docs 스킬로 확인한 [평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)에 따라, 지침의 효과를 모의 테스트의 통과 여부와 구분하고 고정 자료·반복 비교를 사용한다. 현재 작업은 새로운 모델 선택이나 전처리 변경이 아니다.

## 무엇을 고정하는가

| 항목 | 조건 |
| --- | --- |
| 자료 | v4 validation 6종·12사진, 3회 반복 |
| 저장 Vision | `run-9EINEQ/repeat-1..3`의 원래 Vision 신호. 최종 결합 관찰에서 역산하지 않음 |
| 모델 | 두 조건 모두 기존 `gpt-5.6-sol`; 별칭이므로 미래의 제공자 snapshot 동일성까지 보장하지 않음 |
| 입력 | 기존 40% 중앙 크롭, 색상/대비 × 0/90/180/270도 8장/면. 원본·전처리·요청 본문 해시 대조 |
| 요청 설정 | `reasoning=low`, `detail=high`, `max_output_tokens=1400`, `store=false`, 동일 출력 스키마 |
| 바꾸는 것 | OCR `instructions`만 |
| 후처리 | 기존 Vision/OCR 결합, 검색, 등급, 안전 기준, scorer 재사용 |

양면을 각각 요청하면 향후 완전한 비교는 최대 **72회 OCR 요청**이다: 6사례 × 2면 × 3회 × 2조건. Vision 요청은 0회다. 같은 사례·회차 안에서 A/B를 짝지으며 먼저 실행하는 조건은 사례/회차에 따라 교대한다. 이는 18개 독립 제품이 아니라 **6제품의 18회 반복 관측/조건**이다.

기존 저장 OCR은 역사적 비교 자료다. 새 지침만 다시 실행해서 과거에 유리했던 OCR 결과와 비교하지 않고, 향후 실제 실험에서는 기존 지침도 새로 실행해야 한다. 실패한 조건을 과거 OCR로 대체하거나 재시도하지 않는다.

## 실행: 로컬 준비만

Node 24를 사용하는 저장소 루트에서:

```sh
npm run pill:ocr:ab --workspace @care-atlas/backend -- prepare
```

사전 조건은 기존의 비공개 validation 자료, `run-9EINEQ`의 조건/3개 회차 기록, 고정 카탈로그, 기존 진단 baseline 및 사람 판독 비교 보고서다. 비공개 자료가 없는 checkout에서는 준비 불가로 종료한다. 합성 단위 테스트는 이 자료 없이도 실행된다.

출력은 Git 제외 폴더 `verification-artifacts/pill-photo-ocr-ab/plan-*`에 새로 생성한다.

- `plan.json`: 설정·코드·runtime·자료 해시, 요청 이미지 해시/해상도, A/B 지침과 본문 해시, 실행 순서.
- `frozen-vision.json`: 18개 저장 Vision 및 출처·사례·원본·양면 요청 해시 연결. 과거 OCR은 참고용으로만 보관.
- `images/*.png`, `preview.html`: OCR 요청에 사용할 동일 이미지의 로컬 점검용 사본. 외부 전송 아님.

과거 원본·보고서를 덮어쓰지 않는다. 생성 도중 코드/자료가 달라지면 중단한다. 현재 기본 요청 본문 18개가 과거와 같고, 84개 저장 관찰 검색 결과(72개 교차 조합 포함)가 기존 baseline과 같은지도 확인한다. 과거 보고서의 코드 해시나 성능 수치를 새 코드에 맞춰 바꾸지 않는다.

이전 `pill:human:oracle` 명령은 당시 코드 해시까지 고정한 재현 명령이다. 이번 OCR 소스 변경 후 이를 재실행하면 `prior_calculation_code_changed`로 중단할 수 있다. 해당 보호 장치를 완화하지 않으며, 기존 사람 판독 결과는 보존하고 이번 prepare에서 별도의 동작 보존 검사를 수행한다.

## 비교·안전 검사

`executeOcrAbComparison`은 주입한 실행기만 받으며 기본 네트워크 전송 기능이 없다. 현재 테스트는 합성 provider 응답으로 72회 호출 순서와 결합/scorer 연결을 검증한다. 실행기에는 OCR 본문만 전달하고, 정답·사람 판독·카탈로그·저장 Vision은 보내지 않는다. 사례 ID만 유지한 이미지 요청 바꿔치기도 바인딩 해시로 거부한다.

실패 시 해당 사례를 분모에서 빼지 않는다. 앞면 실패 시 뒷면 요청은 생략하지만 사례/조건은 실패로 남기며, 다른 예정 사례는 유지한다. 전체 6제품의 scorer 최소 표본 gate는 그대로 사용하고, 5제품/과거 외형 1제품 결과는 별도 보조 집계다. 작은 집계로 공식 통과 판정을 만들지 않는다.

## 실제 실험 전에 남은 준비

현재 prepare CLI는 실제 실험을 시작하지 못한다. 향후 승인 후 실행 경로를 연결할 때 다음을 검증해야 한다.

1. 준비물 전체의 코드/runtime/이미지/저장 Vision/요청 해시 재검증 및 명시적 전송 동의.
2. `extractReviewedPillPhotoOcr`의 기존 allowlist·bounded transport 재사용. Vision은 호출하지 않음.
3. 요청 시작/종료, 사용량·지연·제공자 응답 모델, 실패와 부분 성공한 면의 파싱 관찰을 빠짐없이 보관. 현재 양면 helper는 한 면 실패 시 전체 실패를 반환하므로 **부분 응답 기록 연결은 후속 필요**하다. 원본 HTTP 응답이 없는 과거 기록을 복원했다고 쓰지 않는다.
4. 새로운 두 조건을 같은 저장 Vision과 결합하고, 전체 결과를 비교. 중단/미완료 실행은 공식 성공으로 집계하지 않음.
5. 사람이 검수한 무각인·로고·판독 불가 안전 사례 확보. 현재 12면은 글자 있는 면 11개, 무각인 1개이며 판독 불가/로고 양성 사례가 없어 이 안전 성능을 입증할 수 없다.

## 사전에 제안하는 개발 성공 기준

- 문제 면 두 곳의 사람 판독 문자열이 OCR 후보에 각각 3회 중 최소 2회 포함되는지 확인한다. 문자 비교는 대소문자·공백 정규화만 사용하고 혼동 문자 확장을 판독 성공으로 세지 않는다.
- 전체 6제품 × 3회에서 recall@5 18/18, recall@1 최소 11/18을 목표로 한다. 새 legacy와의 짝지은 차이도 함께 제시한다.
- strong wrong 0, 재촬영 대상 후보 노출 0, 반복별 결과·편차를 기록한다.
- 5제품/과거 외형 1제품 집계를 병기한다. 현재 공식 각인을 읽어야 했다고 과거 외형 사진에 요구하지 않는다.

위 기준은 **아직 실험하지 않은 개발 목표**이며 운영 승인 기준을 대신하지 않는다. v5는 이번 실험에서 제외하고, 이후 개선의 최종 확인에는 새로운 미사용 자료가 필요하다. 지침 변경의 효과가 없으면 기본값을 승격하지 않는다.
