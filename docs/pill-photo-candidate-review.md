# 공식 후보를 참고한 사진 재판독 (#141)

## 목적과 범위

사전 밖 문자열을 제거하는 이전 오프라인 필터에서는 순위 개선이 없었다. 이번 변경은 **사진을 다시 볼 때 공식 후보 간 차이를 참고하면 각인 판독이 개선되는가**를 실제 API로 확인하는 선택형 실험 경로다. 기본 사진 추출·결합·검색·사용자 API는 바꾸지 않는다.

1. 기존 validation의 저장된 최종 결합 특징으로 실제 검색을 실행.
2. 사용자 반환 제한 전 상위 50품목에서 최대 100개의 **완전한 공식 외형 레코드**를 준비.
3. 사진과 익명 공식 특징을 함께 제시하여 각인을 재판독.
4. 다시 읽은 각인만 기존 검색기에 연결. 모델의 후보 선택/순서를 답이나 검색 순위로 직접 사용하지 않음.

상위 50품목 경계는 이 개발 실험의 자원 제한이며 일반화가 검증된 최적값이 아니다. 원래 후보에 들어오지 못한 정답을 몰래 추가하지 않는다. 이 범위에 정답이 포함됐는지는 요청을 만든 **뒤에** 평가용으로 별도 기록한다.

## 모델에 전달하는 것

- 기존과 동일한 `gpt-5.6-sol`, reasoning `low`, 이미지 detail `high`, `store:false`, tools 없음.
- 앞면과 뒷면 각각: 기존 맥락 이미지 1장 + 컬러 회전 4장 + 대비 강화 회전 4장. 총 18개의 기존 전처리 보기이며 새 촬영/새 전처리는 아님.
- 실수할 수 있는 기존 관찰 특징과 익명 공식 후보의 제형·모양·색상·양면 각인·분할선·마크 존재 여부.
- 공식 누락은 `null`, 설명 포함 여부는 별도 필드로 유지. 공식 누락을 무각인으로 변환하지 않음.

약명·제조사·성분·품목코드·정답·사람 판독·기존 정답 순위·공식 이미지 URL은 전달하지 않는다. 모델용 카드는 물리적 특징만 명시적으로 복사한다. 후보마다 두 면은 동일한 공식 레코드에 속하며, 후보/보류의 서로 다른 외형도 섞지 않는다. 원래 정렬 순서가 힌트가 되지 않도록 레코드 digest 정렬 후 익명 참조를 부여하고 digest 자체는 전송하지 않는다.

모델 응답은 각인 관찰과 최대 5개 레코드의 짧은 가시적 일치/충돌 기록이다. 긴 사고 과정이나 확률을 요청하지 않는다. `readings_observed`, `needs_retake`, `no_supported_candidate`를 허용하므로 사전 중 하나를 강제로 선택할 필요가 없다.

OpenAI Docs의 [구조화 출력 지침](https://developers.openai.com/api/docs/guides/structured-outputs)에 따라 엄격한 스키마와 별도의 서버 검증, 거절/불완전 응답 처리를 사용했다. 스키마 준수는 관찰 정확도를 보장하지 않는다. [이미지 입력의 한계](https://developers.openai.com/api/docs/guides/images-vision#limitations)에 언급된 작은 문자·회전·부정확한 묘사를 이번 결과의 실제 원인이라고 단정하지 않는다.

## 적용·안전 경계

- 기존 사진/양면/파손/제형/판독 품질 차단을 통과하지 못하면 새 요청을 하지 않음.
- 후보 자격이 없는 held-only 외형은 모델의 후보가 될 수 없음.
- 원래 사진 품질·양면 일치·모양·색상·제형·분할선은 유지. 누락 면이나 직접 관찰한 무각인을 후보 정보로 뒤집지 않음.
- 변경된 각인 후보는 기존 `imprintCandidates`에 적용하되 해당 면의 가시성을 **partial 이하**로 제한. 사전을 보고 얻은 판독을 독립적인 확인으로 취급하여 strong으로 승격하지 않음.
- API 장애·불완전·형식 오류는 실패. 모델의 재촬영/근거 부족은 별도 abstention. 과거 성공으로 대체하거나 성공 사례만 골라 재실행하지 않음.
- 사전 후보 점검 기록은 진단용이고 직접 품목 선택·정렬·자동 복약 등록에 사용하지 않음.

## 실행

Node 24, 저장소 루트에서 먼저 전송 없이 준비:

```sh
npm run pill:candidate:review --workspace @care-atlas/backend -- prepare
```

생성된 plan 경로에 대해서만 명시적 승인 후 실행:

```sh
npm run pill:candidate:review --workspace @care-atlas/backend -- run --plan verification-artifacts/pill-photo-candidate-review/plan-XXXXXX --allow-validation-transfer
```

계획·코드·자료·카탈로그·원본 요청 해시를 재검증한 뒤에만 키를 읽는다. 프로세스 `OPENAI_API_KEY`가 없으면 `front/.env.local`을 로드한다. 키는 요청 인증 헤더에만 사용하고 로그나 Git에 기록하지 않는다. 비공개 입력이 없는 checkout에서는 실행 불가이며 합성 테스트는 별도로 실행 가능하다.

현재 실험 입력은 고정된 `run-9EINEQ/repeat-1..3`의 validation 6품목·12사진·18관측이다. 요청은 최대 18회, 동시 2회, 재시도 0회. holdout/임의 모델/다른 사진 경로 옵션은 없다. 고정 HTTPS endpoint 외 전송과 리다이렉트, **40MiB 초과 요청 및 1MiB 초과 응답**을 거절한다. 준비 단계와 전송 단계에서 동일한 직렬화 바이트 상한을 사용한다. HTTP 오류 본문·키가 반사된 응답은 저장하지 않는다.

18개 보기의 실제 직렬화 크기를 기준으로 로컬 요청 상한을 설정했다. [OpenAI Docs의 이미지 입력 요건](https://developers.openai.com/api/docs/guides/images-vision#image-input-requirements)의 2026-09-09 확인값(총 요청 최대 512MB)보다 제한적이다. 크기 제한 보완은 모델·프롬프트·전처리 이미지 변경이 아니다.

## 기록과 해석

`verification-artifacts/pill-photo-candidate-review/`는 Git 제외 경로다.

- `plan-*/plan.json`, `images/`, `coverage.json`: 코드·사진·기존 특징·후보·요청 연결과 요청 후 정답 포함 여부 진단.
- `run-*/condition.json`: 실제 승인 범위, 계획 연결, 고정 조건.
- `started-*.json`: 전송 시도 전에 남긴 요청/이미지 해시와 요청 바이트 수. 이 파일만으로 외부 전송을 입증하지 않음.
- `response-*.json`: 수신한 정상 HTTP JSON 원문. 구조화 내용의 거절/형식 검증은 별도이며 원문 파일이 있다고 판독 성공인 것은 아님.
- `case-*.json`: 응답 상태·usage·제공자 모델·시간, 새 판독과 적용 필드, 기존/변경 결과와 상세 진단.
- `report.json`, `report.md`: 6품목 주 집계, 과거 외형 v4-v05 제외 5품목, 해당 1품목의 별도 집계.

실패·abstention도 분모에 포함한다. 공통 `summarizePillPhotoCaseScores`와 검색/안전 진단을 재사용하며 작은 보조 집계로 공식 합격 gate를 대체하지 않는다. 이 경로는 `officialPassDecision:null`로 운영 합격을 선언하지 않는다.

report v2의 `attemptedReviews`는 로컬 전송 함수 진입 수, `requests`는 `trace.dispatched:true`인 fetch 호출 시도 수다. 로컬 검증 차단은 후자에 포함하지 않는다. fetch 호출도 제공자 수신·과금의 증명과 같지는 않으며 HTTP 상태·request ID·usage를 별도 확인한다.

이 비교는 **저장 1차 관찰 + 추가 후보 참고 재판독 단계 전체의 효과**다. 새로 사진을 받아 처음부터 실행한 성능, 후보 힌트 없는 재판독과의 차이, 새로운 블라인드 성능은 별도 미검증이다. 후보 힌트가 판독을 유도할 수 있고 제공자 모델 별칭의 내부 버전도 달라질 수 있다. 기존 v5 holdout은 튜닝하지 않으며 최종 개선 확인에는 새 미사용 자료가 필요하다.
