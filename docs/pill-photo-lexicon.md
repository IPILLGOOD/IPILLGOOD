# 각인 사전·크롭 오프라인 점검 (#141)

## 결론 — 2026-09-09

고정 validation에서 **사전에 없는 판독 문자열을 제거하는 것만으로 정답 순위가 개선되지 않았다.** 이 필터는 기본 검색/추출 경로에 채택하지 않았다. 이번 결과는 모델이 사진을 읽을 때 사전을 참고하거나 후보의 차이를 다시 관찰하는 방법까지 효과가 없다는 뜻은 아니다.

- 기존 컬러 크롭 12면과 전체 맥락 이미지 12장을 점검한 결과, 알약 전체가 크롭 안에 포함됨. 잘림 때문에 각인이 누락된 면은 발견하지 못함.
- 새 Vision/OCR 요청, 사진 외부 전송, 카탈로그 수집 없음.
- 모델·프롬프트·전처리·결합·검색 가중치·등급·안전 기준 변경 없음. 추가 코드는 오프라인 진단 명령과 테스트뿐임.
- 정상 validation 6제품 × 3회 기록을 모두 사용. 유리한 회차 선택, 실패 분모 제외, holdout 개선 조건 적용 없음.

## 비교 방법

고정 카탈로그의 각 면 `imprint`를 NFKC·대문자·공백 제거로 정규화하여 사전을 작성했다. 품목코드 중복은 제품 수에서 제거하고, 외형 variant 레코드 수와 제품 수는 별도로 집계했다. `rawImprint`의 설명이나 `mark`를 문자 판독값으로 바꾸지 않았다.

저장 실행 `run-9EINEQ/repeat-1..3`에서 기존 Vision/OCR 결합 함수를 재사용한 최종 특징을 기준으로 다음 두 조건을 짝지어 비교했다.

| 조건 | 개입 |
| --- | --- |
| baseline | 기존 결합 특징 그대로 검색 |
| filtered | **결합 후** 면별 `imprintCandidates`에서 사전에 정확히 없는 문자열만 제거 |

남은 문자열의 원문·순서는 유지하고, 판독 상태·직접 관찰한 무각인·사진 품질 등 다른 필드는 바꾸지 않았다. 후보를 모두 제거하게 되는 면은 무각인/판독 불가로 조작하지 않고 별도 `blocked`로 남기도록 했다. 차단이나 추출 실패도 예정된 18회 분모에 포함한다. 이 자료에서는 차단 0회였다.

정답 품목과 사람 판독은 검색 이후 진단에만 사용한다. 사전 이웃 문자열을 생성하는 보조 계산은 문자열 공간의 모호성 확인용이며, 관찰이나 검색 입력에 새 후보를 넣지 않는다. 기존 검색과 진단 순수 함수를 사용하며 검색 알고리즘을 별도로 복제하지 않았다.

## 사전 규모와 한계

| 항목 | 수 |
| --- | ---: |
| 카탈로그 레코드 | 25,387 |
| 서로 다른 품목코드 | 25,370 |
| 정규화된 비어 있지 않은 각인 문자열 | 14,218 |
| 여러 품목에 공통으로 존재하는 각인 문자열 | 2,576 |
| 같은 문자열을 가진 최대 품목 수 | 498 (`10`) |

각인 문자열이 사전에 존재해도 사진을 맞게 읽었다는 뜻은 아니다. 예를 들어 잘못 읽힌 `ML`도 10품목, `C3`도 17품목의 사전에 존재하므로 이 필터를 통과한다. 사람 판독 `CI` 역시 12품목에 존재한다. 집계는 전체 카탈로그 기준이며 실제 후보 자격과 양면 variant 비교는 기존 검색기가 결정한다.

공식 문자열에는 영숫자 외 기호·설명도 섞여 있다. 정규화된 `imprint`의 비ASCII 포함 면 출현은 1,624회지만, 이것이 한글이 실제 각인된 약 1,624종이라는 뜻은 아니다. 이번 사전에서는 임의의 영숫자 강제 변환을 하지 않았다. 설명·로고·문자 결측을 구분하지 않은 일괄 제약은 별도의 검증이 필요하다.

## 결과

각 칸은 **baseline → filtered**. 18회는 독립적인 18제품이 아니라 동일 6제품의 3회 반복 관측이다.

| 범위 | 제품 / 반복 관측 | recall@1 | recall@5 | recall@20 |
| --- | --- | --- | --- | --- |
| 전체 주 집계 | 6 / 18 | 11/18 → 11/18 | 16/18 → 16/18 | 17/18 → 17/18 |
| 과거 외형 사례 제외 | 5 / 15 | 8/15 → 8/15 | 13/15 → 13/15 | 14/15 → 14/15 |
| 과거 외형 v4-v05만 | 1 / 3 | 3/3 → 3/3 | 3/3 → 3/3 | 3/3 → 3/3 |

5제품/1제품은 보조 진단일 뿐 공식 6제품 평가를 대체하지 않는다. 공식 최소 표본 gate를 바꾸지 않았으며, 이 도구의 `officialPassDecision`은 `null`이다.

개입이 발생한 것은 18관측 중 3관측이다.

| 사례 / 회차 | 변경된 앞면 후보 | 정답의 반환 제한 전 순위 | 실제 반환 순위 |
| --- | --- | --- | --- |
| v4-v06 / 1 | `5 A`, `S A` → `S A` | 2 → 2 | 2 → 2 |
| v4-v03 / 2 | `파마`, `ML` → `ML` | 5 → 5 | 5 → 5 |
| v4-v06 / 2 | `5 A`, `S A` → `S A` | 45 → 45 | 양쪽 모두 Top 20 밖 |

다른 15관측은 입력과 공개 검색 결과 전체가 동일하다. 위 3관측은 삭제된 관찰·비교 근거 등이 달라졌지만 정답 순위는 그대로였다. 사람이 읽었다고 기록한 문자열을 삭제한 사례는 없었다. 기존 검색에는 이미 `10`과 `I0`, `C1`과 `CI`의 제한적 혼동 문자 비교가 있어, 이런 경우도 사전 존재 확인만으로 추가 판독 근거가 생기지 않았다.

두 조건의 strong wrong과 retake candidate exposure는 모두 0이었다. 그러나 정상 사진 중심의 작은 자료이며 판독 불가/로고 양성 사례가 없어, 이를 안전 성능 입증으로 해석하지 않는다. 새 전체 순위·상세 사유는 현재 코드 재구성이지 당시 저장된 내부 로그가 아니다.

## 크롭 점검의 해석

`plan-1edq7I`에 연결된 원본 12장·컬러 12장·맥락 12장의 해시가 계획과 일치했다. 원본은 3000×4000이고, 중앙 1200×1200 영역을 컬러 1024×1024로 만든 입력이다. 12면 모두 알약 전체와 여백이 남아 있었다.

v4-v03 앞면의 부드러운 획, v4-v06 뒷면의 낮은 대비는 관찰했지만 조명·원본·크롭·모델 중 무엇이 실패 원인인지 확정하지 않았다. 이번 시각 점검은 모든 회전·대비 강화 이미지를 검사한 것이 아니다. 더 타이트한 크롭의 효과, 중앙을 벗어난 사진의 성공 여부는 미확인이다.

## 재현과 산출물

Node 24의 저장소 루트에서:

```sh
npm run pill:lexicon --workspace @care-atlas/backend
```

이 명령은 고정된 비공개 validation, 저장 실행, 사람 판독, 진단 baseline 파일을 요구한다. 임의 실행·모델·holdout·live 옵션을 받지 않으며 키/환경 파일을 읽지 않는다. 자료가 없거나 바인딩/보존 검사가 실패하면 종료 코드 1이다. 종료 코드 0은 진단 생성 성공이지 인식 합격이 아니다. 비공개 자료 없는 checkout에서도 합성 단위 테스트는 실행 가능하다.

로컬 결과는 Git 제외 폴더에 새로 생성하며 과거 기록을 덮어쓰지 않는다.

- `verification-artifacts/pill-photo-lexicon/audit-IKi192/report.json`: 사전 빈도·신호별 원문·사전 이웃·사람 판독 연결·18관측 상세 비교·현재 코드/입력 해시. 초기 `audit-TurWbW`는 보존하고, 진단 완료 건수 표기를 명확히 한 뒤 새 폴더에 재실행한 결과임.
- 같은 폴더 `report.md`: 6/5/1제품 집계와 18관측의 순위·후보/보류 상태.

## 검증 기록

- 백엔드 전체 **466/466**, skip 0. 신규 사전 합성 테스트 8개 포함.
- strict TypeScript 및 대상 ESLint 통과. ESLint는 기존 루트 pages 경로 안내만 출력.
- `git diff --check` 및 신규 파일 공백 검사 통과. CLI 도움말 정상, `--live`는 자료 로딩 전에 종료 코드 1로 거절.

- 원래 입력의 공개 검색 결과 **84/84 동일**, 저장 교차 조합 72개 포함. 이는 필터 조건과의 차이가 아니라 **진단 전후 기존 동작 보존 검사**다.
- 보호 입력 **317파일** 및 계산 코드 **11파일**의 실행 전후 해시 동일. 과거 holdout은 baseline 무변경 대조만 수행했고 필터 조건을 적용하지 않음.

## 다음 실험 하나

단순 사전 필터는 채택하지 않는다. 이번 비교로 잘못 읽힌 짧은 문자열도 사전에 존재함을 확인했으므로, 다음에는 준비된 [OCR 지침 A/B](pill-photo-ocr-ab.md)의 실행 경로를 연결해 **사진의 문자 획을 확인하는 지침의 효과**를 고정 입력에서 비교하는 것을 제안한다. 아직 효과가 확인된 개선안은 아니다.

두 조건의 모델·이미지·저장 Vision·결합·검색은 동일하게 유지하고 기존 지침도 같은 실험에서 다시 실행해야 한다. 목표는 문제 면의 실제 사람 판독값 포함, 전체 6제품 × 3회 recall@5 18/18 및 recall@1 최소 11/18, 새 기준 조건 대비 순위 손실·안전 위반 없음이다. 모든 실패와 반복 편차를 기록하고, 이 목표를 달성해도 새 미사용 사진의 평가 없이 일반화/운영 성능으로 선언하지 않는다. 이번 작업에서는 실제 A/B API 실행을 하지 않았다.
