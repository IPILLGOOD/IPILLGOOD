# 한국어 식사/영양 자료 탐색

사용자가 확인한 질환을 선택하면 관련 한국어 식사·영양 자료를 최대 8개 반환합니다. 병원·학회 자료, 네이버 블로그·공개 카페와 유튜브를 포함하며, 제목·플랫폼·요약·원문 링크를 표시합니다. 자료 필터는 이미 받은 목록에서 동작하므로 추가 요청하지 않습니다.

## 질환과 요청 범위

프로필의 `ConfirmedConditionsEditor`에서 질환명, 선택 코드와 의료진 진단 확인 여부를 편집합니다. 문서에서 확인한 질환도 함께 관리합니다. 서버는 최대 50개, 중복, 길이, 사용자 확인과 기존 ID를 검사합니다. 변경하지 않은 항목은 ID·문서 출처를 유지하고, 이름이나 코드를 바꾸면 새 ID와 프로필 확인 출처를 부여합니다. 질환명·코드의 의학적 정합성을 자동 판정하는 사전은 없습니다.

`/nutrition`은 확정 질환 ID와 표시명을 전달합니다. 클라이언트는 `/api/nutrition/explore`에 `conditionId`만 보내고 서버가 세션·동의·출처·호출 제한과 해당 계정의 확정 질환을 확인합니다. 외부 검색에는 서버가 확인한 질환명·코드만 사용하며 이름·계정 ID·문서·약 목록은 전달하지 않습니다. AI가 질환을 등록하거나 확정하지 않습니다.

## 검색 계약

| 항목 | 현재 값 |
|---|---|
| 결과 수 | 최대 8개 |
| 서버 요청 제한 시간 | 35초 |
| 최대 출력 토큰 | 2,600 |
| 검색 컨텍스트 | `low` |
| 웹 도구 호출 | 프롬프트상 최대 4회 권장; 코드가 강제하는 횟수 상한은 아님 |
| 공급자 요청·재시도 | 버튼 클릭당 요청 1회, SDK 자동 재시도 0회 |
| 브라우저 제한 시간 | 50초 |
| 앱 호출 제한 | 영양 검색 전용 6회/분 |
| 결과 캐시 | 공개 질환별 24시간, 검색·검증 버전으로 분리 |

예산의 기준은 [AI 검색기](../backend/src/ai/nutrition-exploration.ts), 응답 검증은 [자료 계약](../backend/src/nutrition-exploration.ts)입니다. 같은 서버 인스턴스에서 동일 질환의 동시 요청은 진행 중인 검색을 공유합니다. 개인 HTTP 응답에는 `private, no-store`를 적용합니다.

## 출처와 결과 해석

서버는 스키마, HTTPS, 검색 출처와 URL 일치, 한국어 신호, 질환 관련성, 중복과 사업·캠페인 소개 여부를 확인합니다. 식단·식재료·조리·장보기·외식 같은 실천 자료를 요청하며 질환의 일반 원인·진단·치료 정보만 있는 자료는 제외합니다.

본문·자막을 확인한 자료와 검색 미리보기만 확인한 자료를 구분합니다. 미리보기는 네이버와 유튜브를 포함한 자료에서 허용될 수 있으며 원문 정독이나 한국어 자막 확인을 뜻하지 않습니다. 별도 크롤러·자막 API는 없습니다. 언어·접근·관련성 판단 일부는 모델 보고와 발췌에 의존하므로 URL 검증만으로 요약 정확성·의학적 검수가 입증되지는 않습니다. 원문 발췌와 내부 선별 신호는 화면·캐시에 반환하지 않습니다.

## 오류와 검증

검색 0건도 정상 결과로 캐시하며 허구나 외국어 번역 자료로 채우지 않습니다. 실패·서버 시간 초과는 503, 요청 제한은 429로 구분합니다. 이전 결과는 페이지 메모리에 유지하고, 늦게 도착한 응답은 요청한 질환에 연결합니다.

일시 제한은 유효한 `Retry-After` 또는 기본 60초를 표시하며 자동 재호출하지 않습니다. 명시적 quota 오류는 사용 한도 확인 안내를 표시합니다. 로그는 안전한 오류 코드·시간·개수·제한 수치로 한정하고 질환명·키·조직 ID·원문 오류는 남기지 않습니다.

전체 검증은 합성 응답으로 인증·동의·질환 소유 범위, 출처·언어·8건 제한, 목록·필터·오류·0건을 검사합니다. 실제 자료 선정 품질과 원문 충실도는 별도 평가가 필요합니다. 이 기능은 개인별 식단 처방이나 복용약 안전성 판단을 하지 않습니다.
