- Vision 문자 exact와 결합 후 문자 exact는 공식 문자 필드가 있는 면만 계산한다. 공식 필드 누락을 무각인 정답으로 취급하거나 로고 판독 성공률로 확대하지 않는다.

- 두 조건에서 OCR도 새로 호출하므로 OCR의 자연 변동이 결합 결과에 영향을 줄 수 있다. Vision 단독 지표와 OCR 원문/결합 결과를 함께 비교하며, 모든 변화가 Vision 수정 때문이라고 단정하지 않는다.
- 같은 이름의 모델이 동일한 가중치라고 보장할 수 없다. 반환 모델 태그·요청 ID·실행 시각과 조건 해시를 보존한다.

### 원신호에서 확인한 다음 개선 지점

- `v4-v03` 앞면: 개선 Vision은 3회 모두 판독 불가로 남겼지만 면별 OCR은 매회 서로 다른 문자를 반환했다. 뒷면 판독은 두 조건 모두 유지됐다. 앞면의 부정확한 OCR 값이 결합 결과에 들어가며 순위가 달라졌으므로, 지시문을 더 자세히 썼다는 사실만으로 앞면 판독이 해결됐다고 볼 수 없다. 기준선 3회차 역시 앞면 문자 exact 없이 정답이 1위였으므로 순위와 판독 정확성을 구분해야 한다.
- `v4-v06` 뒷면: 개선안 2·3회에는 Vision의 복수 후보 안에 공식 문자열이 들어갔지만, OCR은 다른 문자를 반복 반환했다. 같은 회차에서 Vision 단독 검색 1위가 결합 후 2위였다. 이는 OCR 결합이 항상 정답 순위를 높이지 않는다는 관측이지, OCR을 무조건 제거하거나 Vision을 항상 믿어도 된다는 근거는 아니다.
- `v4-v03`의 개선안 Vision 전체 특징 JSON은 3회 동일했지만 결합 순위는 5·2·5였다. 이는 OCR 대안이 바뀌어 검색 근거가 달라진 경우다. 전체 72면 관찰에서 정확 문자가 결합 중 소실되거나 후보 상한으로 잘린 사례는 없었으므로, 결합 후보 상한을 늘리는 방향은 근거가 없다.
- **바로 다음 단위는 추가 API 없는 OCR 고정 교차 재생**을 권한다. 같은 회차의 기준/개선 Vision 두 개와 기준/개선 OCR 두 개를 기존 결합·검색으로 교차 재생해 Vision 수정과 OCR 자연 변동의 영향을 분리한다. 이는 저장 신호의 진단이며 신규 추론 정확도나 독립 평가 수치가 아니다.
- 그 결과를 바탕으로 기존 Vision·검색을 고정한 각인 OCR 판독 개선을 설계한다. 현재 한 응답으로 합쳐져 있는 회전별 관찰을 분리해 출처·모호성을 확인하는 방식을 검토하되, 여러 모델·크롭·검색 규칙을 동시에 바꾸거나 이 두 사례의 정답을 프롬프트에 넣지 않는다.

이번 단계에서는 OCR·결합·검색을 추가 변경하지 않았다. 현재 holdout은 계속 동결하며, 사용자 UI·운영 연결은 새 독립 평가 및 안전 기준을 충족하기 전까지 진행하지 않는다.

## 재현 명령과 자료 구분

Node 24, 설치된 의존성과 승인된 로컬 v4 validation 자료가 필요하다. 루트에서 실행하며 서버·Firebase 로그인은 필요하지 않다. `prepare`와 `pill:trial:compare`는 키나 네트워크 없이 실행된다. `run`만 `front/.env.local`의 키로 과금 요청을 보낸다.

```sh
# 각 준비 명령이 반환한 plan 디렉터리와 preview.html을 확인한다.
npm run pill:trial --workspace @care-atlas/backend -- prepare
npm run pill:trial --workspace @care-atlas/backend -- prepare --protocol validation-structured-observation-v1

# 각각의 실제 plan 절대 경로로 치환한다. 각 명령은 54요청이다.
node --env-file=front/.env.local --experimental-strip-types backend/scripts/pill-photo-trial.ts run --plan <baseline-plan> --live --confirm-reviewed-transfer
node --env-file=front/.env.local --experimental-strip-types backend/scripts/pill-photo-trial.ts run --plan <candidate-plan> --protocol validation-structured-observation-v1 --live --confirm-reviewed-transfer

# 기존 파일은 보존하고 새 comparison.json / comparison.html을 생성한다.
npm run pill:trial:compare --workspace @care-atlas/backend -- --baseline <baseline-run> --candidate <candidate-run>
```

- CLI는 두 개의 명시된 프로토콜만 허용한다. 기본값은 기존 프롬프트이며 환경변수로 실험 모델을 바꾸지 못한다. 새 프롬프트의 holdout/evaluation 적용은 자료 로딩 전에 거부한다.
- 비교기는 condition 해시, 6제품 × 3회 × 3요청 완결성, 회차별 결과에서 다시 계산한 지표, 고정 입력·런타임·검색/OCR/전처리 코드 해시를 검사한다. Vision 지시문 외의 요청 설명·이미지 배치·OCR 본문 해시가 달라지면 비교를 거부한다.
- 프로토콜 선택을 위한 실험 실행기·조건 기록 코드 및 신규 프롬프트 파일 변경은 보고서에 별도로 드러낸다. 이 허용 목록은 임의 변경 코드가 의미상 동등함을 자동 증명하지 않으므로 코드 리뷰도 필요하다.
- 비교기는 이미지 바이트를 읽지 않으므로 전체 API 본문 해시를 재계산하지 못한다. 실제 실행기가 전송 전에 원본에서 재생성한 요청·PNG와 plan을 대조한 기록을 사용한다. 저장 파일의 일관성 검사는 공급자 측 실제 요청의 독립 증명이 아니다.
- 새 비교 도구의 종료 코드 0은 보고서 생성 성공이다. `decision`과 모든 회차를 함께 확인하며 `no_clear_gain`도 정상적인 실험 결과다. 불완전 실행이나 잘못된 조건은 exit 1이다.
- 이미지·원신호·요청 ID·전체 비교 결과는 Git 제외된 `verification-artifacts/`에 남긴다. Git에는 이 문서의 비민감 집계·조건 지문·재현 명령을 남기며 개인별 복용 약 목록이나 사진을 추가하지 않는다.
- 기존 자료 없이도 새 프롬프트 계약 및 비교 도구의 합성 테스트를 실행할 수 있다. 실제 휴대폰 수치 재계산에는 비공개 자료 또는 승인된 저장 결과가 필요하다. API를 재호출하면 같은 수치가 보장되지 않는다.

실행 후 면별 원신호는 다음 명령에 각 `repeat-N` 경로를 전달해 대조한다. 이 명령도 외부 요청이 없다.

```sh
npm run pill:diagnose --workspace @care-atlas/backend -- --run <baseline-run>/repeat-1 --compare <candidate-run>/repeat-1
```

## 코드 검증 범위

- 백엔드 전체 **404개 통과, skip 0**. 이 컴퓨터에는 기존 비공개 fixture가 있다. 이 수치를 깨끗한 체크아웃에서도 비공개 자료 없이 동일하다고 주장하지 않는다.
- 새 프롬프트 계약 4개, 비교·CLI 테스트 13개는 합성/공개 fixture만 사용한다. 기존 trial 9개도 후보 프로토콜의 저장·전송 버전 일치와 안전 지표만 달라지는 반복 차이를 검사하도록 보완했다.
- backend strict TypeScript와 변경 TS 파일 ESLint, `git diff --check` 통과. 기존 `pill:regression` 6개 통과, 해당 명령의 외부 요청 0회.
- 기본 프롬프트 보존, 실제 Vision instructions만 변경, 선택 버전 기록 및 holdout 자료 로딩 전 차단을 독립 코드 리뷰로 교차 확인했다.
- 사용자 UI·운영 코드 경로를 추가하지 않았다. 원격 CI, 운영 빌드, Firebase/UI 풀사이클 검증은 이번 작업에서 실행하지 않았다.
- 기존 안전 회귀는 저장된 관찰을 사용하는 검색·평가 경계 검사다. 새 Vision 프롬프트가 모든 부정 사진을 안전하게 거부한다는 실사진 검증은 아니다. 정상 6제품에서 강한 오답·재촬영 상태 후보 노출이 0이어도 실제 파손·다중 알약 사진의 안전성을 입증하지 않는다.
