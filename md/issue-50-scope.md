# #50: 신규 계정 빈 상태 안내

이번 브랜치는 이슈의 빈 상태 UI만 다룬다. 로그인·권한 검사, 프로필 저장 모델, 기본 나이 제거와 온보딩 완료 상태 모델은 변경하지 않는다.

- 문서·복약·몸 상태·안부 기록이 전혀 없는 일반 계정에는 시작 안내 표시
- 미동의이면 프로필 확인, 저장된 동의가 있으면 첫 문서 등록을 다음 행동으로 제안
- 문서 등록은 선택 사항이며 동의 후 문서 없이 몸 상태 기록으로 이동 가능
- 아직 없는 분석 확정 기능을 제공한다고 안내하지 않고 원문 대조를 안내
- 빈 화면은 개인화 질문을 생성하지 않으며 0/0·0% 진행률이나 Push 활성화를 먼저 노출하지 않음
- 기존 기록이 있는 계정과 데모는 기존 화면 유지. 예정 회차가 없는 날에는 진행률 생략

이는 #42의 서버 동의 게이트를 대신하지 않는다. #50 전체는 프로필·동의 온보딩, 직접 URL 제한, 기본값 제거와 #43 연결이 남아 있으므로 종료하지 않는다.

회귀 테스트: `npm test --workspace @care-atlas/front`의 `getting-started.test.mjs`.

## 확인한 결과

- 프런트 단위 테스트 44개·백엔드 테스트 90개, 타입 검사, 린트, 프로덕션 빌드 통과
- 합성 계정의 미동의·동의 완료 두 상태에서 다른 다음 행동과 문서 없이 기록하는 선택 경로 확인
- 시작 안내에서 프로필로 이동하는 링크 확인, 키보드 포커스와 접근성 이름 확인
- 320/768/1024/1440px 가로 넘침 없음, 기존 디자인 토큰과 명시적인 단계·링크 사용
- 두 빈 계정의 화면 조회 후 에뮬레이터 `careAnalyses`, `questionSets`, `agentRuns`가 모두 0건임을 확인
