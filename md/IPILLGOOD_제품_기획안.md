# IPILLGOOD 제품 기획

IPILLGOOD는 고령자와 보호자가 처방 정보를 이해하고, 매일의 복약·몸 상태를 남겨 다음 진료에 활용하도록 돕는 서비스다. [문제 정의와 근거](IPILLGOOD_근거자료.md)

## 사용자와 핵심 과업

주 사용자는 여러 약을 복용하는 가족을 돌보는 보호자다. 어르신은 직접 응답하거나 연결된 기기로 같은 돌봄 공간을 이용할 수 있다. 본인 응답과 보호자의 관찰은 구분해서 기록한다.

| 과업 | 제공하는 기능 |
|---|---|
| 처방을 이해하기 | 처방전·약봉투·진단서 이미지/PDF 분석, 원본 대조·수정·확정, 쉬운 약 설명과 공식 출처 |
| 오늘 복약 확인하기 | 예정 시각·완료 여부, 복용·미복용 기록, 프로필에서 설정하는 PWA 기기 알림 |
| 변화를 기록하기 | 몸 상태·증상·메모, 최근 기록을 참고한 맞춤 안부, 지난 복약 응답 수정 |
| 약 정보를 찾아보기 | 제품명·성분명 공식 검색, 알약 앞뒤 사진의 공식 비교 후보 |
| 식사 자료 찾기 | 확인받은 질환별 한국어 자료·영상 요약과 원문 링크 |
| 진료 준비하기 | 복약·증상 대시보드, 의료진 질문, 최근 7일 Care Report 출력 |
| 함께 이용하기 | Google 로그인, 연결 코드로 추가 기기 로그인, 방문자별 비식별 체험 |
| 정보 관리하기 | 프로필·동의·확정 질환, 연결 해제, 건강정보 삭제, 회원 탈퇴·복구 |

## 이용 흐름

1. Google 또는 연결 코드로 로그인한다. 가입 전에는 비식별 샘플을 체험할 수 있다.
2. 대상자 프로필과 건강정보 처리 동의를 확인한다.
3. 처방 문서를 등록하고 추출된 약·복용량·횟수·기간을 원본과 대조해 확정한다. 분석 완료만으로 복약 계획에 반영하지 않는다.
4. 오늘 할 일에서 복용과 몸 상태를 남긴다. 맞춤 질문은 최근 기록을 참고하며 미응답을 정상 상태로 바꾸지 않는다.
5. 대시보드와 보고서에서 기록을 모아 보고 의료진과 상담한다.

모바일 PWA의 하단 메뉴는 오늘 할 일·복용약·빠른 이동·식사/영양·프로필이다. 빠른 이동은 가운데에 있으며 복용 여부·몸 상태 기록, 문서 등록과 사진 검색을 연다. 알림·계정 설정은 프로필에 있다. 맨 위에서 당겨 새로고침할 수 있고 로그인 실패 후 재시도할 수 있다.

## 사진 검색과 공식 정보

같은 알약의 앞뒤 사진에서 외형·각인을 읽고 식약처 전체 카탈로그와 비교한다. 비교 후보·판단 보류·재촬영·무결과·처리 오류를 구분한다. 사진 결과로 약을 확정하거나 복용약에 자동 등록하지 않는다. 공식 카탈로그는 최신성·무결성을 검사하며 오래되면 검색을 중단한다.

공식 약 검색은 제품과 성분을 기준으로 원문을 찾고, 쉬운 설명이 실패해도 공식 정보와 링크를 유지한다. 영양 탐색은 확인한 질환의 자료를 찾는 기능이며 개인별 식단 처방이나 약물 상호작용 판정이 아니다.

## 연결과 데이터 관리

계정 소유자는 최초 10분 안에 입력할 연결 코드를 발급한다. 연결된 기기 한 대가 같은 돌봄 공간을 이용하며 새 기기 로그인 시 이전 세션을 교체한다. 연결 사용자는 소유자의 계정 삭제 권한을 갖지 않는다. 여러 Google 계정의 데이터를 병합하지 않는다.

문서 원본과 사진 검색 사진·결과는 앱에 영구 저장하지 않는다. 문서 분석 결과, 확정한 복약과 사용자 기록은 계정 범위에서 보존한다. 건강정보 삭제는 별도 본인 확인을 거치며, 탈퇴는 즉시 이용을 중단하고 3개월 동안 복구용으로 보관한 후 영구 삭제한다. 같은 Google 계정의 새 인증과 명시적 확인이 있어야 복구한다. [상세 정책](../docs/account-deletion.md)

## 제품의 경계와 검증 과제

IPILLGOOD는 진단·처방·복용 중단·용량 변경·대체 약 추천을 하지 않는다. 기록을 바탕으로 증상과 약 사이의 인과관계를 단정하지 않는다. 문서 추출과 사진 후보는 원본 및 의료진·약사의 확인을 필요로 한다.

웹 기능 구현과 실제 의약품 식별 성능은 별개다. 동결한 사진 평가에는 실패한 holdout 결과가 있으며, 소규모 개발 세트의 성공을 운영 정확도로 일반화할 수 없다. [사진 평가와 한계](../docs/pill-photo-evaluation.md)

자동 검증은 합성 계정과 외부 응답을 사용한다. 실제 고령 사용자 과업 수행, 의료진의 설명·질문 검토, 실기기 접근성·PWA·OAuth·알림 도착과 실제 검색 자료 품질은 별도로 평가해야 한다. 여러 보호자 역할·소유권 이전, 공식 카탈로그 자동 갱신은 아직 지원하지 않는다.

구현 구조는 [아키텍처](architecture.md), 실행·설정은 [개발 안내](../docs/development-guide.md), 가치 검증은 [사업성 문서](value-and-viability.md)를 참고한다.
