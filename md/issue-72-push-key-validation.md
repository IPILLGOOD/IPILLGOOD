# #72: PWA 재진입 시 Push 키 검증·복구

## 기존 동작과 변경

기존에는 오늘 화면의 알림 카드가 마운트될 때 구독 등록 여부만 조회했다. 현재 서버의 VAPID 공개키와 `PushSubscription.options.applicationServerKey`를 비교하지 않았고, 백그라운드에서 돌아오는 PWA를 재검사하는 공통 수명주기도 없었다.

이제 인증된 앱 공통 영역의 `PushStatusProvider`가 설치형 PWA·모바일 지원 환경에서 아래 시점에 검사한다. 공개 랜딩·로그인에는 설치하지 않는다.

- 첫 앱 진입 및 React 마운트
- 앱 내부 경로 이동
- `visibilitychange`로 화면이 다시 보일 때
- `pageshow`(뒤로 가기 캐시 복원 포함), `focus`, `online`
- standalone 표시 모드 변경

검사는 숨겨진 화면에서 생략하고 동시에 발생한 요청은 하나로 합친다. 매 검사마다 `/api/push/config`와 기기 상태를 `no-store`로 조회한다. 일정한 간격의 백그라운드 폴링은 하지 않는다.

## 검사 범위

- 현재 서버 공개키의 형식과 구독에 바인딩된 공개키의 바이트 일치
- 브라우저 알림 권한, 지원 여부 및 구독의 명시적 만료 시각
- 서버 구독이 현재 로그인 계정·대상·기기에 속하는지 확인
- 서버 endpoint 해시와 현재 브라우저 endpoint 해시 비교: 재등록 일부 실패 시 오래된 서버 구독을 정상으로 오인하지 않음
- 마지막 Push 서비스 응답 401/403을 인증 설정 문제 가능성으로 안내. 키 불일치로 단정하지 않음
- 키 메타데이터를 제공하지 않는 브라우저는 `확인 불가`를 알리며 정상 키를 추측하거나 자동 해제하지 않음

이는 매 진입마다 실제 Push를 보내는 수신 시험이 아니다. 공개키 일치는 비밀키·서명·외부 Push 서비스의 가용성·기기 표시까지 증명하지 않는다.

## 복구와 동의 경계

- 검사는 GET만 사용한다. 자동 재구독, 권한 팝업, 서버 등록·해제·발송을 하지 않는다.
- 키 불일치 또는 만료 시 공통 안내와 `알림 다시 연결하기` 버튼을 제공한다.
- 사용자가 누르면 현재 공개키를 다시 읽고, 불일치·만료된 구독만 해제한 뒤 재등록한다.
- 정상 키 구독은 재사용한다. 해제 실패 시 후속 생성·등록을 멈춘다.
- 변경 직후 다시 조회하여 실제 서버 반영 상태를 확인한다. 오류를 성공으로 표시하지 않는다.
- 계정 전환·로그아웃으로 공통 영역이 해제되면 진행 중 등록 요청을 중단하고, 대기 중 권한/구독 결과를 새 계정에 업로드하지 않는다.
- 신규 계정은 브라우저에 이전 구독이 있어도 명시적 활성화 전 자동 등록하지 않는다.

## 검증

- 프런트 테스트 55개, 백엔드 테스트 91개 통과
- 키 일치·교체·확인 불가·만료·권한 거부·설정 장애·서버 401/403·업로드 실패·해제 실패·계정 전환 중 취소 회귀 테스트
- 서비스 워커 준비·요청 시간 제한, PWA 복귀 이벤트와 리스너 정리 테스트
- 타입 검사·린트·프로덕션 빌드 통과
- 로컬 앱 + Firestore 에뮬레이터 + 합성 Push API로 실제 React 흐름 확인: 대시보드 진입 검사, 키 교체 후 PWA 복귀 경고, 명시적 재연결, 문서 경로 이동 시 재검사
- 공통 경고의 320/768/1024/1440px 가로 넘침 없음, 최종 재연결·경로 이동 흐름에서 브라우저 오류 로그 없음
- 합성 구독은 실제 Push 서비스에 전송하지 않음. 실기기 Safari/Chrome의 설치형 PWA 수신 시험은 별도 필요

## 배포 후 확인 절차

1. 운영 키를 무작정 교체하지 말고 먼저 별도 시험 환경과 시험 계정·기기를 준비한다.
2. 기존 키로 명시적 구독 후 신규 키 쌍을 시험 서버에 배포한다.
3. PWA를 종료·재실행하거나 백그라운드에서 복귀하여 공통 경고를 확인한다.
4. 재연결 버튼을 누르고 경고 해제·서버 기기 상태를 확인한다.
5. 운영자 테스트 발송 및 예정 알림의 수신·표시를 확인한다. 이 단계는 사용자에게 실제 알림을 보낸다.
6. 정상 키 유지, 거부 권한, 오프라인·재연결, 여러 탭, 로그아웃·다른 계정 전환도 확인한다.

운영 VAPID 키 변경·배포·실제 발송은 이번 작업에서 수행하지 않았다. #73의 전체 구독/로그아웃 복구 이슈를 종료하는 변경도 아니다.
