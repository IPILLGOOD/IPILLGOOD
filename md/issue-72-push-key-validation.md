# #72: PWA 재진입 시 Push 키 검증·복구

## 기존 동작과 변경

기존에는 오늘 화면의 알림 카드가 마운트될 때 구독 등록 여부만 조회했다. 현재 서버의 VAPID 공개키와 `PushSubscription.options.applicationServerKey`를 비교하지 않았고, 백그라운드에서 돌아오는 PWA를 재검사하는 공통 수명주기도 없었다.

이제 인증된 앱 공통 영역의 `PushStatusProvider`가 설치형 PWA·모바일 지원 환경에서 아래 시점에 검사한다. 공개 랜딩·로그인에는 설치하지 않는다.

- 첫 앱 진입 및 React 마운트
- 앱 내부 경로 이동
- `visibilitychange`로 화면이 다시 보일 때
- `pageshow`(뒤로 가기 캐시 복원 포함), `focus`, `online`
- standalone 표시 모드 변경

검사는 숨겨진 화면에서 생략하고 동시에 발생한 요청은 하나로 합친다. 매 검사마다 `/api/push/config`와 기기 상태를 `no-store`로 조회한다. 권한이 이미 허용된 기존 활성 구독은 필요하면 이어서 자동 복구한다. 일정한 간격의 백그라운드 폴링은 하지 않는다.

## 검사 범위

- 현재 서버 공개키의 형식과 구독에 바인딩된 공개키의 바이트 일치
- 브라우저 알림 권한, 지원 여부 및 구독의 명시적 만료 시각
- 서버 구독이 현재 로그인 계정·대상·기기에 속하는지 확인
- 서버 endpoint 해시와 현재 브라우저 endpoint 해시 비교: 재등록 일부 실패 시 오래된 서버 구독을 정상으로 오인하지 않음
- 마지막 Push 서비스 응답 401/403을 인증 설정 문제 가능성으로 안내. 키 불일치로 단정하지 않음
- 키 메타데이터를 제공하지 않는 브라우저는 `확인 불가`를 알리며 정상 키를 추측하거나 자동 해제하지 않음

이는 매 진입마다 실제 Push를 보내는 수신 시험이 아니다. 공개키 일치는 비밀키·서명·외부 Push 서비스의 가용성·기기 표시까지 증명하지 않는다.

## 복구와 동의 경계

- 상태 조회 자체는 GET만 사용하며 실제 알림을 발송하지 않는다.
- 브라우저 권한이 `granted`이고 현재 계정·기기에 활성 구독이 있으면 키 불일치·만료를 안내 없이 자동 복구한다. 이 경우 공통 경고와 `알림 다시 연결하기` 버튼을 표시하지 않는다.
- 자동 복구는 공개키·현재 계정의 활성 상태를 다시 읽고, 불일치·만료된 구독만 해제한 뒤 새 키로 재등록한다. `Notification.requestPermission()`이나 권한 요청을 포함하는 라이브러리 구독 함수를 호출하지 않는다.
- 권한이 `default`·`denied`이면 자동 해제·생성·등록하지 않는다. 수동 활성화에서만 권한을 요청할 수 있다.
- 정상 키 구독은 재사용한다. 해제 실패 시 후속 생성·등록을 멈춘다.
- 변경 직후 다시 조회하여 실제 서버 반영 상태를 확인한다. 중간의 불일치 상태를 화면에 먼저 노출하지 않는다.
- 자동 복구 실패는 연결 실패 상태를 유지하며, 60초 이내의 추가 복귀 이벤트에서는 재등록을 반복하지 않는다. 이후 접속·복귀 이벤트에서 재시도한다. 업로드만 실패했다면 이미 생성한 새 구독을 재사용한다.
- 계정 전환·로그아웃 또는 수동 알림 변경 시 진행 중 자동 복구 요청을 중단한다. 각 비동기 경계에서 취소·권한 상태를 재확인하고 대기 중 구독 결과를 새 계정에 업로드하지 않는다.
- 신규 계정·다른 계정 또는 사용자가 꺼 둔 기기는 브라우저 권한이 허용돼 있어도 자동으로 활성화하지 않는다.
- 자동 복구 업로드에는 `onlyIfActive` 조건을 붙이고 서버 트랜잭션에서도 현재 계정·대상의 활성 상태를 확인한다. 조회 직후 다른 화면에서 해제한 구독을 복구 요청이 다시 활성화하지 않는다.

## 검증

- 프런트 테스트 66개, 백엔드 테스트 93개 통과
- 키 일치·교체·확인 불가·만료·권한 거부·설정 장애·서버 401/403·업로드 실패·해제 실패·계정 전환 중 취소 회귀 테스트
- 서비스 워커 준비·요청 시간 제한, PWA 복귀 이벤트와 리스너 정리 테스트
- 허용 권한 자동 복구·권한 요청 0회·권한 변경 중단·사용자 opt-out 보존·실패 후 재시도 및 새 구독 재사용 회귀 테스트
- 타입 검사·린트·프로덕션 빌드 통과
- 로컬 앱 + Firestore 에뮬레이터 + 합성 Push API에서 키 교체 후 복귀 시 자동 복구 확인: 권한 요청 0회·경고 0회·해제/생성/업로드 각 1회
- 연속 복귀 이벤트 30회와 경로 이동 후에도 추가 업로드 없음, 오늘 화면에서 정상 연결 상태 확인
- 수동 알림 해제 후 연속 복귀 시 서버 비활성 상태 유지, 자동 재등록 없음
- 320/768/1024/1440px 가로 넘침 없음, 브라우저 오류·경고 로그 없음
- 합성 구독은 실제 Push 서비스에 전송하지 않음. 실기기 Safari/Chrome의 설치형 PWA 수신 시험은 별도 필요

## 배포 후 확인 절차

1. 운영 키를 무작정 교체하지 말고 먼저 별도 시험 환경과 시험 계정·기기를 준비한다.
2. 기존 키로 명시적 구독 후 신규 키 쌍을 시험 서버에 배포한다.
3. PWA를 종료·재실행하거나 백그라운드에서 복귀한다.
4. 이미 허용된 알림이 안내·권한 팝업 없이 자동 재연결되고 서버 기기 상태가 갱신됐는지 확인한다.
5. 운영자 테스트 발송 및 예정 알림의 수신·표시를 확인한다. 이 단계는 사용자에게 실제 알림을 보낸다.
6. 정상 키 유지, 거부 권한, 오프라인·재연결, 여러 탭, 로그아웃·다른 계정 전환도 확인한다.

운영 VAPID 키 변경·배포·실제 발송은 이번 작업에서 수행하지 않았다. #73의 전체 구독/로그아웃 복구 이슈를 종료하는 변경도 아니다.
