# 알약 사진 캡처 평가 세트

`pill-photo-capture-eval-2026-09-02-v2`는 사진 특징 추출과 식약처 카탈로그 후보 포함 여부를 개선 전후로 비교하기 위한 고정 자료다. 공개 원본 16장을 검수해 반대 면 한 쌍씩 총 8개 사례로 구성했다.

## 분할 원칙

| 분할 | 사례 | 사용 목적 |
| --- | ---: | --- |
| 기존 개발 세트 | 정상 4건 | 2026-08-31의 0/4 기준 결과 보존, 문제 분석 |
| `validation` | 정상 4건 | 전처리·프롬프트·OCR·결합 규칙을 반복 개선 |
| `holdout` | 정상 4건 | 검증 기준과 구현을 고정한 뒤 마지막에 한 번 평가 |

검증과 보류 평가 사진은 기존 개발 사진과 파일·SHA256이 겹치지 않는다. 다만 세 분할 모두 **동일한 4개 품목의 서로 다른 촬영 컷**이다. 따라서 이 결과는 회전과 촬영 컷 변화에 대한 재현성만 확인하며, 처음 보는 약이나 실제 사용자 휴대폰 사진에 대한 일반화 성능을 뜻하지 않는다.

`holdout` 결과를 본 뒤 프롬프트, 전처리, OCR, 검색 규칙 또는 임계값을 바꾸면 더 이상 보류 평가가 아니다. 그 경우 새 사진을 별도 보류 평가 세트로 지정하고 버전을 올려야 한다.

## 정답과 모델 입력의 분리

- `manifest.json`의 품목기준코드와 공식 특징은 **추론이 끝난 뒤 평가할 때만** 사용한다.
- 품목별 `mappingEvidenceUrl`은 5자리 접수번호와 제품 외형의 공개 검수 근거이고, `expectedOfficialRecordSha256`은 가져온 시각을 제외한 고정 식약처 레코드 지문이다.
- 모델에는 사진 바이트와 시각 특징 추출 지시만 전달한다. 품목기준코드, 접수번호, 공식 각인, 파일명, 카탈로그 후보를 전달하지 않는다.
- 추론 입력 로더는 불투명한 사례 ID와 사진 경로만 반환하며, 테스트에서 정답 필드가 섞이지 않음을 확인한다.
- 모델은 약명·성분명·품목기준코드를 생성하지 않는다. 사진에서 관찰한 특징만 반환하고, 서버가 식약처 API로 수집한 고정 카탈로그와 비교한다.

## 무결성과 범위

- 원본 PNG 16장의 크기와 SHA256을 고정했다.
- 각 분할에는 4개 품목이 한 번씩 포함되고 각 사례에는 검수된 공식 앞·뒷면이 하나씩 들어간다.
- 정답 특징은 PR의 고정 식약처 카탈로그 `pill-photo-shared-2026-08-31-v1`과 일치해야 한다.
- 개인정보가 없는 공개 사진만 포함한다. 사용자 사진·API 키·로그·가공 중간 산출물은 포함하지 않는다.
- 흐림, 어두움, 여러 알약, 실제 파손, 복잡한 배경은 이 자료에 없다. 해당 안전 평가를 이 세트의 성능으로 대신하지 않는다.

## 정답 연결 검증

```sh
npm run pill:labels --workspace @care-atlas/backend
npm run pill:labels:live --workspace @care-atlas/backend
```

첫 명령은 Git에 고정한 전체 식약처 카탈로그에서 접수번호 근거 → 품목기준코드 → 공식 외형이 정확히 한 레코드로 연결되는지 검사하며 외부 요청을 보내지 않는다. 두 번째 명령은 로컬 `front/.env.local`의 식약처 키를 사용해 동일한 네 품목코드를 현재 v03 API에서 각각 조회한다. 사진과 AI 추출값은 식약처에 보내지 않으며, 공식 레코드가 사라지거나 복수로 바뀌거나 외형·메타데이터가 달라지면 성공으로 처리하지 않는다.

## 저장된 특징 결과 채점

특징 추출 실행은 아래 필드를 가진 JSON을 저장한다. 각 사례에는 최종 `pillPhotoFeaturesSchema` 특징 또는 제한된 실패 사유만 들어가며 정답 품목코드는 넣지 않는다.

- 고정된 평가·스키마 버전과 `validation` 또는 `holdout` 분할
- 전처리·Vision·OCR·결합 규칙 버전과 모델명
- 정확히 네 개의 불투명 사례 ID와 추출 결과

검증 분할은 다음처럼 오프라인으로 채점한다.

```sh
npm run pill:score --workspace @care-atlas/backend -- --input <saved-features.json> --split validation
```

구현과 통과 기준을 고정한 후 보류 평가를 실행할 때만 명시적으로 확인한다.

```sh
npm run pill:score --workspace @care-atlas/backend -- --input <saved-features.json> --split holdout --confirm-holdout-final
```

채점은 외부 요청을 하지 않는다. 식약처 고정 카탈로그로 후보를 다시 계산하고 `recall@1·5·20`, 강한 오답, 재촬영 결과의 후보 노출을 기록한다. 현재 작은 후보 제시형 파일럿의 통과 기준은 다음과 같다.

- 네 사례 모두 평가됨
- `recall@5` 4/4
- `strong` 등급의 오답 후보 0개
- 재촬영 대상에서 후보·보류 후보 노출 0건

전체 `strong` 후보 수와 해당 사례 수도 함께 기록한다. 현재 네 품목은 식약처 분할선 정보가 `unknown`이어서 정확한 특징을 넣어도 `strong` 등급이 생성되지 않을 수 있다. 따라서 strong 오답 0개를 단독으로 안전성 증거로 해석하지 않는다.

이 기준은 전처리·OCR 변경의 회귀를 찾기 위한 **캡처 수준 기준**이다. 통과해도 운영 정확도나 새로운 품목·사용자 사진에 대한 일반화를 주장하지 않는다. 결과는 `verification-artifacts/pill-photo-score/` 아래에 저장되며 Git에는 포함하지 않는다.

## 전처리 변형

`pill-photo-alpha-pca-detail-contrast-v1`은 검수된 원본의 크기·SHA256을 다시 확인한 뒤 다음 세 입력을 결정적으로 만든다.

- `context`: 원래 방향과 색상을 유지한 전체 외형, 긴 변 1280px 이하
- `alignedColor`: 투명 마스크의 주축이 충분히 긴 경우에만 수평 보정한 컬러 각인 화면, 긴 변 1600px
- `alignedContrast`: 같은 수평 화면을 회색조·1~99% 명암 정규화·제한적 선명화한 OCR 보조 화면, 긴 변 1600px

회전은 약의 투명 마스크에 대한 알파 가중 주성분 축으로 계산한다. 장축/단축 비가 1.2 미만이면 방향 근거가 부족한 원형으로 보고 회전하지 않는다. 변환 과정에서 원본의 EXIF·XMP·텍스트 청크와 투명 영역의 숨은 RGB는 제거하며, 출력 크기·회전 각도·축 비율·출력 SHA256을 메타데이터로 남긴다.

주축 보정은 알약의 긴 축만 수평으로 만들 뿐 글자의 올바른 위·아래 방향은 결정하지 못한다. 실제 자료에는 장축과 직각으로 인쇄된 각인도 있다. 따라서 메타데이터에 OCR이 검사해야 할 `0°·90°·180°·270°` 네 방향을 고정하며, 다음 OCR 단계는 어느 한 방향만 정답으로 가정해서는 안 된다.

색상 판단에는 `context` 또는 `alignedColor`만 사용하며, `alignedContrast`는 각인 판독 보조 신호다. 현재 공개사진 실험 경로는 한 사례를 두 개의 독립 요청으로 처리한다.

1. 범용 Vision은 각 면의 `context`와 `alignedColor`를 보고 외형·품질·복수 각인 후보를 관찰한다.
2. 각인 전용 OCR은 `alignedContrast`의 `0°·90°·180°·270°` 네 방향만 보고 각 면의 문자 후보를 반환한다.
3. 서버 결합기는 동일 판독을 먼저 배치하고 Vision/OCR 단독 판독을 교차 배치해 면당 최대 5개를 유지한다. 두 신호의 후보 집합이 다르면 `partial`로 제한하며, 문자 혼동 확장은 이 단계에서 하지 않고 기존 검색기의 버전 고정 규칙에 맡긴다.

두 요청 모두 약명·성분·품목기준코드·정답 특징·카탈로그 예시를 받지 않는다. 결합 결과에는 각 후보의 Vision/OCR 출처, 원문, 순서, 불일치와 절단 여부가 남는다. 이 파이프라인은 코드·모의 응답 검증을 완료했지만 아직 validation 사진으로 실제 외부 호출·성능 채점을 수행하지 않았으므로, 기존 0/4를 개선했다고 주장하지 않는다.

출처와 접수번호-품목기준코드 대응 근거는 기존 [공유 자료 출처 문서](../pill-photo-fixtures/SOURCES.md)에 기록돼 있다.
